# Release — framework changes pending publication

Bullets here are FINAL changelog entries. `/pfm:release` copies them verbatim into
`releases/vX.Y.Z.md`, then clears this file, keeping this header.

Shape: `- {Tier}: {scope} — {semantic change}`, plus a `#### → For:` line when adopters must act,
and `(cost)` on any env / hook / permission / model-config delta.

## Pending
- B: pfm — Harvester adds configurable SciHubEVA, SciDB, Anna's Archive, LibGen, and Google Scholar adapters alongside Unpaywall and PubMed Central. CLI and MCP results use complete exported artifacts and opaque discovery handles, keeping acquisition URLs, methods, internal paths, and fallback traces private. Provider failures remain explicit, and internal cache files cannot be fetched through the public surface.
- B: pfm — a fleet chat's terminal tab (tmux `set-titles-string`, the label VS Code shows through `${sequence}`) now carries ONE name, the chat's own: a Claude pane renders Claude Code's title with its status glyph stripped, so a `/rename` or `pfm chat name` reaches the tab at once, unclipped, and the label holds still through the spinner; every other engine renders its window name, which name-sync converges. The former `⬢ #{window_name} · #{pane_title}` showed a Claude chat's name twice — the first copy clipped at 24 runes and trailing a rename by a statusline redraw. `pfm chat name` also clips the window name through `gather.WindowNameFor`, like the statusline and name-sync writers, so a name over 24 runes no longer flips the window between its full and clipped spellings. Live servers take the new format on the next name-sync tick; `pfm name-sync` applies it immediately.
- B: pfm — the Professor VS Code extension ships inside pfm: `pfm install --vscode` links it into the `extensions/` of every VS Code product present (desktop, Insiders, VSCodium, Remote-SSH server, a portable install) and adds its **Professor** terminal profile to the + dropdown. The default terminal stays pfm's own `PFM` settings profile: a window reload rebuilds each restored terminal through VS Code's contributed-default lookup, which hands it to the default's extension for a brand-new terminal instead of reattaching — with an extension profile as the default, every reload dropped the open terminals (the pty host shut them down five minutes later). Each new integrated terminal opens the chat picker and carries its chat's live name. The ledger records every link; later installs and updates keep it reconciled without the flag; uninstall removes only links still pointing at pfm's copy. An owned default holding `Professor` moves back to `PFM`, and an older ledger gets the extension linked on the next ordinary install. VS Code settings writes now go THROUGH a symlinked `settings.json` instead of replacing the link with a copy, and a portable install's settings path is `$VSCODE_PORTABLE/user-data/User/settings.json` (it had a stray `data/`). (cost): writes a symlink into each present VS Code `extensions/` directory.
#### → For: VS Code users — run `pfm install --yes --vscode` once (or any install if you opted in before), then **Developer: Reload Window**.
- B: pfm — `pfm update` no longer rolls itself back because live chats are older than it. The spawn audit dated its "born after the layer" line by the staged prompt's mtime, which an install leaves alone when the prompt's bytes don't change, so every chat launched before the `--settings` output-style flag counted as a broken spawn door, doctor exited 1, and the update's doctor gate undid the update. The line is now when this host's current spawn door went live: the later of the prompt's and the running pfm binary's mtime, both named in the report. Chats an older pfm launched report as PREDATES-LAYER (reload to carry the flag).
- B: pfm — a rolled-back update restores the hook files its install rewrote. The previous release's installer recognises only hooks it generates, so a hook only the newer release registered (e.g. `exit-intercept` on UserPromptSubmit) survived the rollback and ran a subcommand the restored binary lacks on every prompt. `pfm update` now snapshots every installer-owned hook file (each account's Claude settings, each Codex hooks file, and their ownership ledger) before the install and restores it on rollback, but only while the file still holds exactly what that install wrote. A file a live chat saved in the meantime is left alone and named as rollback residue.
- B: pfm — an unknown `pfm internal <name>` exits 1, not 2. Exit 2 is Claude Code's blocking hook code, so a hook registered by a different pfm version erased every prompt ("UserPromptSubmit operation blocked by hook") instead of reporting one non-blocking error that names the fix.
- B: pfm — `pfm update` builds its candidate with `-buildvcs=false`. The stage is a git worktree, whose `.git` file cmd/go does not treat as a VCS root, so any stray `.git` directory above it (an empty `$HOME/.git`) failed the build with "error obtaining VCS status".
- B: pfm — a process's birth time on Linux is the kernel's start tick plus boot time, not the `/proc/<pid>` directory's mtime. procfs creates that inode lazily, so the mtime read processes as minutes to hours younger than they are, skewing the spawn audit and Codex thread-to-pane matching.
- B: pfm — `pfm install` run from inside a git worktree of the source clone records the clone itself, not the worktree. A worktree is deleted once its work merges, which left the source marker, `pfm update`, and the global links pointing at nothing.
- B: pfm — `make install` is atomic and leaves no stale processes behind. It builds and smoke-tests the new binary next to `~/.local/bin/pfm`, swaps it in with a single rename (the previous one kept as `pfm.prev`), and restarts the MCP daemon. Only after all of that succeeds does it sweep every pfm process still running the replaced image: TERM, then KILL, then a re-scan that fails loudly on a survivor. A failed build or smoke test changes nothing; a failed daemon restart restores `pfm.prev` and kills nothing. (cost): a successful `make install` ends stale pickers, and any session whose chat MCP server ran the old image reconnects it with `/mcp`.
