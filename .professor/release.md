# Release — framework changes pending publication

Bullets here are FINAL changelog entries. `/pfm:release` copies them verbatim into
`releases/vX.Y.Z.md`, then clears this file, keeping this header.

Shape: `- {Tier}: {scope} — {semantic change}`, plus a `#### → For:` line when adopters must act,
and `(cost)` on any env / hook / permission / model-config delta.

## Pending
- B: pfm — Harvester adds configurable SciHubEVA, SciDB, Anna's Archive, LibGen, and Google Scholar adapters alongside Unpaywall and PubMed Central. CLI and MCP results use complete exported artifacts and opaque discovery handles, keeping acquisition URLs, methods, internal paths, and fallback traces private. Provider failures remain explicit, and internal cache files cannot be fetched through the public surface.
- B: pfm — a fleet chat's terminal tab (tmux `set-titles-string`, the label VS Code shows through `${sequence}`) now carries ONE name, the chat's own: a Claude pane renders Claude Code's title with its status glyph stripped, so a `/rename` or `pfm chat name` reaches the tab at once, unclipped, and the label holds still through the spinner; every other engine renders its window name, which name-sync converges. The former `⬢ #{window_name} · #{pane_title}` showed a Claude chat's name twice — the first copy clipped at 24 runes and trailing a rename by a statusline redraw. `pfm chat name` also clips the window name through `gather.WindowNameFor`, like the statusline and name-sync writers, so a name over 24 runes no longer flips the window between its full and clipped spellings. Live servers take the new format on the next name-sync tick; `pfm name-sync` applies it immediately.
- B: pfm — the Professor VS Code extension ships inside pfm: `pfm install --vscode` links it into the `extensions/` of every VS Code product present (desktop, Insiders, VSCodium, Remote-SSH server, a portable install) and adds its **Professor** terminal profile to the + dropdown. The default terminal stays pfm's own `PFM` settings profile: a window reload rebuilds each restored terminal through VS Code's contributed-default lookup, which hands it to the default's extension for a brand-new terminal instead of reattaching — with an extension profile as the default, every reload dropped the open terminals (the pty host shut them down five minutes later). Each new integrated terminal opens the chat picker and carries its chat's live name. The ledger records every link; later installs and updates keep it reconciled without the flag; uninstall removes only links still pointing at pfm's copy. An owned default holding `Professor` moves back to `PFM`, and an older ledger gets the extension linked on the next ordinary install. VS Code settings writes now go THROUGH a symlinked `settings.json` instead of replacing the link with a copy, and a portable install's settings path is `$VSCODE_PORTABLE/user-data/User/settings.json` (it had a stray `data/`). (cost): writes a symlink into each present VS Code `extensions/` directory.
#### → For: VS Code users — run `pfm install --yes --vscode` once (or any install if you opted in before), then **Developer: Reload Window**.
- B: pfm — `pfm update` no longer rolls itself back because live chats are older than it. The spawn audit dated its "born after the layer" line by the staged prompt's mtime, which an install leaves alone when the prompt's bytes don't change, so every chat launched before the `--settings` output-style flag counted as a broken spawn door, doctor exited 1, and the update's doctor gate undid the update. The line is now when this host's current spawn door went live: the later of the prompt's and the running pfm binary's mtime, both named in the report. Chats an older pfm launched report as PREDATES-LAYER (reload to carry the flag).
- B: pfm — a rolled-back update restores the hook files its install rewrote. The previous release's installer recognises only hooks it generates, so a hook only the newer release registered (e.g. `exit-intercept` on UserPromptSubmit) survived the rollback and ran a subcommand the restored binary lacks on every prompt. `pfm update` now snapshots every installer-owned hook file (each account's Claude settings, each Codex hooks file, and their ownership ledger) before the install and restores it on rollback, but only while the file still holds exactly what that install wrote. A file a live chat saved in the meantime is left alone and named as rollback residue.
- B: pfm — an unknown `pfm internal <name>` exits 1, not 2. Exit 2 is Claude Code's blocking hook code, so a hook registered by a different pfm version erased every prompt ("UserPromptSubmit operation blocked by hook") instead of reporting one non-blocking error that names the fix.
- B: pfm — `pfm update` builds its candidate with `-buildvcs=false`. The stage is a git worktree, whose `.git` file cmd/go does not treat as a VCS root, so any stray `.git` directory above it (an empty `$HOME/.git`) failed the build with "error obtaining VCS status".
- B: pfm — a process's birth time on Linux is the kernel's start tick plus boot time, not the `/proc/<pid>` directory's mtime. procfs creates that inode lazily, so the mtime read processes as minutes to hours younger than they are, skewing the spawn audit and Codex thread-to-pane matching.
- B: pfm — `pfm install` run from inside a git worktree of the source clone records the clone itself, not the worktree. A worktree is deleted once its work merges, which left the source marker, `pfm update`, and the global links pointing at nothing.
- B: pfm — `make install` is atomic and leaves no stale processes behind. It builds and smoke-tests the new binary next to `~/.local/bin/pfm`, swaps it in with a single rename (the previous one kept as `pfm.prev`), and restarts the MCP daemon. Only after all of that succeeds does it sweep every pfm process still running the replaced image: TERM, then KILL, then a re-scan that fails loudly on a survivor. A failed build or smoke test changes nothing; a failed daemon restart restores `pfm.prev` and kills nothing. (cost): a successful `make install` ends stale pickers, and any session whose chat MCP server ran the old image reconnects it with `/mcp`.
- B: pfm — `pfm install` and `pfm uninstall` no longer change numbers in the JSON files they rewrite. `~/.claude.json` and every account registry, Claude `settings.json`, and Codex `hooks.json` were decoded into Go floats and written back, so any integer beyond 2^53 (a counter or id) came back rounded — `9007199254740993` became `…992`. Those rewrites now decode numbers verbatim; malformed JSON is still refused.
- B: pfm — Codex chats can reach the fleet again. On macOS the shared MCP daemon (`pfm mcp serve`, the transport every Codex chat uses) ran on launchd's bare `/usr/bin:/bin:/usr/sbin:/sbin`, where tmux is not, so every chat tool a Codex chat called answered as if no chat were live: `chat_inject` refused with "matched no live chat" and `chat_whoami` found "no live Codex tmux seat". The same bare PATH left `pfm name-sync` (the launchd job that turns chat names into tmux window names, and so into VS Code tab titles) renaming nothing while exiting 0. Every pfm service unit — both launch agents and both systemd services — now renders its PATH from one search path covering `~/.local/bin`, the Homebrew prefixes and the system directories, and a tmux that cannot start fails every fleet probe and name resolution with its cause instead of reporting an empty fleet.
- B: pfm — the MCP daemon restarts itself onto a new build. It exits (status 75) when its own binary is replaced, after in-flight calls finish, and launchd's KeepAlive or systemd's `Restart=on-failure` brings it back on the binary now on disk — so an install path that only swaps the binary no longer leaves the daemon serving the old one for days.
- B: pfm — Codex 0.154 chats are named without false alarms. 0.154 renames a thread without printing "Session renamed to", so `pfm chat new`, `pfm chat branch`, the post-`/clear` name re-apply and every dream seat reported a chat that was named on the first try as "never asked for a thread name" (and failed the dream seat), after typing `/rename` twice more into a pre-filled dialog. A rename is now proven from Codex's own `session_index.jsonl`, checked before any retry, the dialog is recognised by its title, and an unreadable ledger reports "could not verify" rather than "unnamed".
- B: pfm — every chat's tmux server is born through ONE creator with ONE option list, so a chat's name reaches its tmux window and its VS Code tab whichever door opened it. The picker's fresh-server routes (new Claude, new OpenCode, agent, Claude resume, OpenCode resume) emitted an attached `tmux new-session` that bypassed pfm's creator: no title policy, `automatic-rename` left on, and a window the running binary renamed (a Claude window read `2.1.257`). The picker, the Codex resume, `spawn`, the Claude launcher and the shell's `cx` now all create the server detached through `spawn.CommandTmux.NewSession`, which applies `config.ChatServerOptions` — the title policy plus `automatic-rename off` — and names the window for its engine until name-sync gives it the chat's name; the eval line only attaches. `cx` reaches that creator through `pfm internal chat-server`, which replaces `pfm internal tmux-titles` and the shim's copy of the option sequence. `pfm name-sync` converges every live server onto the same list, so a server born before this release stops renaming its window on the next tick.
- B: pfm — `pfm chat open` (and the MCP `chat_open`) resumes a Codex or OpenCode chat on its own engine's account. It handed every row the Claude primary account, so a host whose Claude primary was account 2 but which had a single Codex account refused every Codex resume with "Codex account 2 is not in the configured roster". The engine-to-account rule now lives once, in `config.PrimaryAccountFor`, and the picker's two copies of it are one.
- B: pfm — `make install` sweeps stale pfm processes on macOS too. The sweep read `/proc/<pid>/exe`, so on a Mac it reported STALE-UNKNOWN and swept nothing, leaving every picker and chat MCP server started before the install on the old build. Stale detection is now one Go implementation, `pfm internal stale [--sweep]`, which compares each running pfm's executable with the installed binary by device and inode (`/proc` on Linux, `lsof` on macOS); `make stale`, `make sweep-stale` and `make mcp-status` call it, and the redundant `make kill-stale` is gone. `make mcp-restart` restarts the macOS launch agent with `launchctl kickstart -k` and fails loudly unless a new daemon pid appears, instead of pkill-ing it and hoping launchd noticed. (cost): on macOS a successful `make install` now ends stale pickers, and a session whose chat MCP server ran the old image reconnects it with `/mcp`.
- B: pfm — Harvester no longer stores a JavaScript app's shell as the page. A client-rendered site serves one static document for every route; when that shell carried a no-JS explainer longer than the 500-char thin-page floor, `fetch` accepted it at the direct rung and cached it under every URL on the host (`/events` came back byte-identical to `/`, as a success). A page that ships a client bundle or mount point is now checked with one request to a sibling path that cannot exist: the same visible text proves the shell, and the ladder escalates — Jina Reader renders the route, while defuddle, the real-browser rung and a Wayback snapshot are each refused while their content is still the shell. With no renderer the failure is named (`ErrorKind` `app_shell`, with the `fetch.browser` state) and nothing is cached. (cost): one extra GET for each fetched page that ships a client bundle or mount point.
- B: pfm — Harvester's real-browser rung renders headless first. Every fetch that reached it opened a visible Chrome window on the desktop; it now renders headless and spends ONE headed (visible) retry only on a bot wall the headless render met — a headed launch that cannot start (a display-less host) leaves the headless verdict standing. The browser environment also follows pfm upgrades: one an older pfm provisioned kept its interpreter, so it kept running that pfm's worker, and `pfm doctor` printed `source_hash=ok` over it. The next browser fetch now re-provisions a stale environment, and doctor reports `source_hash=SOURCE_STALE(…)` until it does. (cost): the first browser fetch after an upgrade that changes the worker or its lock re-provisions the browser environment.
- A: quality family — `/quality:description`, the law for the one field every session pays for: a `description:` is injected into every chat and every sub-agent spawn whether or not its body loads. Fixed component order (`[TOKEN] {function ≤5 words} — {when}. [Returns {shape}.] [Not for x → home.]`), measured caps (280 chars for a body-bearing entry, 400 when the overrun is entry points / family neighbours / Returns, 600 per MCP tool, 900 per server instruction block), a cut order that takes the mechanism first (`with rumdl`, `via midrun.js`, a model tier), naming law (the name is not respent in the description), family law (a `family:*` chain is legible from descriptions alone, carried by exactly one member), USER-ONLY declared twice (`disable-model-invocation: true` plus the token, since a prompt clause is advisory and the harness flag is not), a `## MCP tools` section for body-less entries (one inline example call with the schema's real field names, the sibling hand-off, the audience boundary, empty-vs-error distinguished), five WRONG→RIGHT pairs measured on live text, and an 11-check Approval gate emitting `APPROVED` / `REJECTED — checks {n,…}` / `UNREAD`. `/pfm` § Descriptions and its file-type laws collapse to a pointer here.
- A: quality family — `/quality:md-forlint`, markdown lint and format mechanics for any project: `check [path]`, `fmt [path]`, `prompt-safe <file>`, `audit`, `profile <path>`. One `rumdl` config at the repo root decides every rule for every path, and its `[per-file-ignores]` table IS the category map — prompt (`.claude/**`, `CLAUDE.md`, templates, injected prompt assets), doc (`docs/**`, engine specs), public (`README`, `INSTALL`, `CHANGELOG`), generated (mirrors — format the source and recompile), record (`releases/`, ledgers, `testdata/` — never reformatted). Measured on this framework: paragraph-collapse reflow −242 bytes / −161 lines over 23 prompt files where sentence-per-line costs +1,048 / +690 and a 100-column wrap costs +2,289 / +1,602, so never wrap; stripping table column padding (`MD060.style = "compact"`) takes 7.4% off a `docs/` tree; the whole professor-owned markdown surface lands −93,404 bytes / −1,524 lines with one word-level change, a mis-numbered ordered list corrected. Carries the gotchas that make or break it: rumdl resolves `[per-file-ignores]` against the CURRENT DIRECTORY (run it from the repo root or every exemption silently misses), an invalid rule option does not fail but prints `Using default values` and formats with the default, and four rules rewrite what they must not — `MD056`/`MD075` delete cells from a malformed table and `MD018`/`MD020` read a line-initial `#20` (a wave, issue or PR number) as a heading missing its space and re-level every real heading below it, so all four are held in `unfixable`; `MD001`/`MD025` would demote a prompt's own H1 sections, which are addressing, not hierarchy. The record category is drawn the same way: a file whose bytes another test asserts is not prose — a staged prompt asset (`prompts_asset_test.go` asserts it equals its template twin, `embed_test.go` pins its SHA-256), a verbatim capture of another system's prompt, a `CHANGELOG.md` whose `#### → For:` markers the release flow copies verbatim, and a per-run wave train are all excluded.
- B: templates + scripts — the markdown format hook is real for the first time: `scripts/format-md.sh` runs `rumdl fmt` under the repo-root `.rumdl.toml` instead of `npx prettier`, so it is a single static binary rather than a network fetch mid-turn, and it names the missing tool on stderr instead of skipping in silence. The policy ships as `templates/project/rumdl-policy.toml`, scaffolded by `pfm init` to `.rumdl.toml` — it must NOT ship named `rumdl.toml`, a name rumdl discovers by walking up from every file it checks, which silently made the blueprint's own copy the governing config for everything beneath it. `/quality:doc` drops the prettier-padding rationale (rumdl compacts tables instead), turns its Approval table into a list, and gains check 9: a dead relative link, a stale anchor or ToC entry, or a byline term, reported mechanically.
