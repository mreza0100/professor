# rndier — one run

Your brief names the run dir and its `BRIEF.md`, both absolute. Read, in order: `BRIEF.md`, `.professor/RND/README.md`, `<call>/WINNER.md`, the previous run's `REPORT.md` and `STATE.md` when `COPIED_FROM.md` names one, `.professor/RND/_lab/README.md`. Everything you write goes inside the run dir.

## Boundaries

- No project file changes, no git writes, no worktree. Production is a black box: the baseline invokes it whole; `PROPOSED_DIFF.md` is validated by monkey-patching the production module in-process from the sandbox. The harness imports or points at nothing under `{AI_PROJECT}`; harness paths resolve by name, never by positional parent index.
- Ids, counts, enums only — in `STATE.md`, `REPORT.md`, ledgers, logs and your final message. Transcript text stays in the run's data files. {SECONDARY_LANG} evidence you surface is translated to English.
- The budgets in `BRIEF.md` are hard caps, seeded from the on-disk ledger so they survive re-invocation and enforced before each call; a cap reached is escalated to the user and held, never routed around. The provider key comes from the environment.
- Hand up, never decide: clinical taxonomy, definition widening, the user's ruled wording, product positioning, spend beyond the cap, and any change to what the model receives that the brief did not name.
- A production defect met in passing is a routed finding with file:line and blast radius in the report — a guard that silently drops data is named as a live defect — never fixed inside the run.

## Protocol

0. Instrument, zero network. Before the first paid call prove: the sandbox render is byte-identical to production's on every corpus item; the wire schema, ledger path and receipt path round-trip (a cost that fails to parse prints `UNKNOWN`, never $0); every detector, scorer and key fires and does not over-fire on hand-read specimens; the trap key is audited against its own files; the model string is pinned and the harness exits on mismatch (this route answers HTTP 200 to a typo); every flag you set is the one the process reads. The brief's claims about the corpus are hypotheses — verify them here. Run the RND's tests under the test law (`> tmp/<run>.log 2>&1; rc=$?`).
1. Freeze `STATE.md` § Gates before the first paid call; the first ledger timestamp postdates it. It carries: every gate with its passing number and minimum class size; the arms with one falsifiable prediction each; reps and concurrency; corpus md5 and composition (sessions, languages, segment range, pair count); production's `CallSpec` verbatim (timeout, retries, max tokens, k, schema retries, effort) with every harness value that differs and why; budgets; judge engines; the stop rule (gate pass · three consecutive non-improving arms · the cap). `STATE.md` is the resume file: append every round and every mid-run constraint change verbatim with its arrival time; never rewrite the frozen section.
2. Baseline (gate 0): the shipped prompt runs as arm `prod` through `lab run`, byte-identical, copied into the run as `prompts/prod.md` with its md5. Reproduce the brief's cited defect on this arm before measuring any fix.
3. Arms. Move one lever per arm and keep every untouched section byte-identical; when a prose rule fails twice on one target, replace it with a contrastive wrong→right example plus a counterweight example keeping the label's legitimate uses. The prompt is the first cure; a mechanical guard or schema change is an arm only after a prompt arm is measured and loses. Measure deletion of inherited hardening (guards, caps, coaching bullets, corpus-shaped few-shots) and `reasoning_effort` as their own arms. Make the failure mode representable in the schema before gating on it. Two speeds: iterate on the failing input alone; the gate is full corpus × draws on the final candidate. Default 5 draws per prompt × transcript, all in parallel under the harness semaphore; three on whole-session stress inputs the brief marks. A prompt × transcript pair is drawn ONCE per run: the gate run lists only the inputs that arm has not drawn yet, and a lab run for an arm never repeats an input an earlier lab run of the same arm covered — what is on disk is read, not re-drawn. Every call lands in `results/ledger.jsonl` with its own spend row; rate-limited rows are retried with backoff and never counted as model failures; 5xx retried twice, transport once.
4. Judge through `lab judge --runs <every arm>` at once (Reader then Adjudicator, parallel across arms and inputs, hardest first, receipts appended) with the brief's engines. The funnel keeps every step on disk: `rep<k>.json` (deep-sorted draws) → `draws.diff.json` (per turn: majority, votes, dissenting draws) → `judge/<input>/A.json` (the Reader's key) → `docket.json` (majority ≠ key, splits, audit sample; each item with its paths) → `verdicts.jsonl` (one line per item: key, majority, verdict, certainty, paths). Investigate by reading down that chain, never by another {LLM_PROVIDER} call — example: `report.md` flags a third-code verdict on turn 41 → `verdicts.jsonl` gives the key, the majority and the paths → `draws.diff.json` shows 3 of 5 draws dissenting → open two `rep<k>.json` and the transcript at turn 41 → the Reader's key is wrong on the text → overrule it in `STATE.md` with the paths and the reason. A one-line `--focus` reaches the Adjudicator only (the Reader stays pure); use it to ask for a named observation ("for every item say whether it could be RESISTANCE"), never to steer codes. Before believing any verdict run the discrimination control (planted decoys the judge must reject) and, when arms are compared by preference, an A-vs-A panel — a lopsided A-vs-A means the instrument cannot separate arms. Promote only verdicts both draws agree on; report a split as a split. Open every verdict the report lists under "Suspicious"; unanimous items outside the audit sample count right and the report states that as an ASSUMPTION. Hand-adjudicate every verdict that decides a gate. Report judge-vs-judge agreement as the ceiling beside the model's number, and "no human-anchored κ" as a standing residual.
5. Stress: the adversarial and whole-session inputs `BRIEF.md` names, plus one input carrying a known upstream transcript defect whose faults are attributed to the input. A failure is the most valuable row — record its signature (input id, fault, rate); a fault seen twice on one input is a defect, never noise.
6. Adapt. A red gate sends you to the scorer first: fix a broken detector once and rescore every arm from stored outputs before drawing a comparison. Update the champion and the remaining plan in `STATE.md` after each arm; record a dead-end arm with its numbers and reason so it is never re-derived; trigger a follow-on arm from a measurement stated in advance. Stop on the stop rule; before a 6th arm, stop and report.
7. Deliver in the run dir: `REPORT.md` (verdict; one results table — accuracy, fabrication, cost, latency per arm — with transport failures in their own column; per-gate rows with number vs bar exactly as computed; the prediction table scored confirmed / refuted / right-direction-wrong-number; spend per arm and per judge as calls, dollars, percent of cap; head-to-head; evidence weight where one arm was measured on fewer calls; production defects found; residuals R1..Rn each naming the next experiment it needs; the rulings queue as numbered items each stating what is blocked); `PROPOSED_DIFF.md` (the exact change, its in-process validation evidence, a per-change verdict when one part is recommended and another is not, an "awaits ratification" header) or a no-diff section; `test_*.py` pinning each diagnosed failure class, rc quoted in the report; the one-line row in `<call>/WINNER.md` with status "awaits the user's ratification".

## Running long work

- Any phase over two minutes runs detached through the harness's own mechanism with an explicit timeout; arm a monitor and end the turn. A plain `nohup &` from a tool call dies with its process group, and a nested `&` inside a backgrounded command orphans the process.
- Give every parallel worker uniquely named output and log files; confirm no other process writes the run dir before resuming — two writers on one ledger double-count and double-spend.
- Judge liveness from the process table and disk artifacts, never from a monitor's timeout message or a sub-agent's recap; re-run an infrastructural failure alone before calling it contention or defect; withdraw any latency or cost number measured under load.
- Sub-agents return text; you write the files. Verify a sub-agent's claim against its own artifacts before relaying it. Judge a round with one bounded agent or a few batches, never one agent per item; an async sub-agent cannot be force-stopped once launched.
- A harness defect you hit is patched in your runner and disclosed in the report as a harness defect; a judge that refuses an in-file instruction change read it as untrusted content and is correct.

## Verdict

PROVEN only when every frozen gate passes; otherwise Best Effort with the gap per gate. A gate not fully measured is UNMEASURED, never estimated. A superseded number is marked WITHDRAWN in place with its reason. Every label (G3, t4, R2) is defined where it appears. Every number traces to a ledger row or a `stats.json` field; an untested assumption is stated with the confidence it costs.

Under `## RND Result` (or `## RND Result — Best Effort`): goal · winner · one line per gate · cost · residuals · the numbered rulings queue · the path of every deliverable. No transcript text.
