# v0.77.0 — 2026-09-14

Harvester stops caching a JavaScript app's empty shell as the page and gains five discovery adapters, the Professor VS Code extension ships inside pfm, global agents reach every Claude account, and `pfm ls` groups resumable chats and stops showing unanswered OpenCode sessions. This is also the first release rehearsed as an adopter would live it: a cheap Codex model installed the previous release on a fresh fenced machine, then updated it — once from v0.76.0 and once from five releases behind — and every defect it tripped on is fixed here, starting with a source install that never recorded its clone and an update that refused the detached checkout the install recipe leaves.

## Verification

Six sonnet reviewers read `origin/main...release/v0.77.0` by area (six reports for six dispatched); every defect they raised was checked against the code, and each fixed one carries a regression test watched FAILING against the unfixed code first — the detached-source update, the three release-notes listing branches, the missing-marker install line, `chat find` across an 8 MB line, the retired MCP tools' absence, the update prompt reading every skipped release, the pre-release version ordering, the no-clone doctor row, resumable name groups, and the OpenCode size and unanswered-session rows. The full pfm suite, `go vet` and the architecture ratchet ran green inside the `dev.sh iso` fence after every change; `cmd/pfm` stays under its line budget by extraction (16079 of 16104), never by raising it.

- A: quality family — `/quality:md-forlint`, markdown lint and format mechanics for any project: `check [path]`, `fmt [path]`, `prompt-safe <file>`, `audit`, `profile <path>`. One `rumdl` config at the repo root decides every rule for every path, and its `[per-file-ignores]` table IS the category map — prompt (`.claude/**`, `CLAUDE.md`, templates, injected prompt assets), doc (`docs/**`, engine specs), public (`README`, `INSTALL`, `CHANGELOG`), generated (mirrors — format the source and recompile), record (`releases/`, ledgers, `testdata/` — never reformatted). Measured on this framework: paragraph-collapse reflow −242 bytes / −161 lines over 23 prompt files where sentence-per-line costs +1,048 / +690 and a 100-column wrap costs +2,289 / +1,602, so never wrap; stripping table column padding (`MD060.style = "compact"`) takes 7.4% off a `docs/` tree; the whole professor-owned markdown surface lands −93,404 bytes / −1,524 lines with one word-level change, a mis-numbered ordered list corrected. Carries the gotchas that make or break it: rumdl resolves `[per-file-ignores]` against the CURRENT DIRECTORY (run it from the repo root or every exemption silently misses), an invalid rule option does not fail but prints `Using default values` and formats with the default, and four rules rewrite what they must not — `MD056`/`MD075` delete cells from a malformed table and `MD018`/`MD020` read a line-initial `#20` (a wave, issue or PR number) as a heading missing its space and re-level every real heading below it, so all four are held in `unfixable`; `MD001`/`MD025` would demote a prompt's own H1 sections, which are addressing, not hierarchy. The record category is drawn the same way: a file whose bytes another test asserts is not prose — a staged prompt asset (`prompts_asset_test.go` asserts it equals its template twin, `embed_test.go` pins its SHA-256), a verbatim capture of another system's prompt, a `CHANGELOG.md` whose `#### → For:` markers the release flow copies verbatim, and a per-run wave train are all excluded.

## Fixed

The launcher now exits 127 when it finds no real Claude binary, and doctor reads that exit from pfm's own launcher as absence: `dep claude … MISSING optional` and `harness-prompt: skipped (no Claude Code binary installed)`, neither counted — the same standing Codex's absence already had. A Claude binary that is present but failing still warns. Found by the release rehearsal: an adopter five releases behind updated, and the update undid itself.

- C: pfm — `pfm ls` groups a resumable `GROUP:NAME` chat with its live namesakes: name groups admitted only live, agent and booting rows, so every ↻ chat named `SOLO:BUILD`, `RR:…` or `RND:…` — Claude or Codex — rendered flat beside a `SOLO (1)` panel holding its sibling.

- C: pfm — OpenCode rows in `pfm ls` stop claiming `0B`: an OpenCode session has no file to measure, so its size shows `—` in the picker and the plain output (the TSV column stays numeric). An OpenCode session with prompts but no assistant reply is empty — hidden and counted in the header's `empty`, like an empty Claude transcript — where one prompt alone used to earn it a row. (cost): the fleet database migrates to schema 9 on first run (one additive `oc_sessions.assistant_count` column); the next index pass fills it.

- C: pfm — the `pfm ls` update check ranks a pre-release build below its own release: a binary stamped `0.78.0-alpha` is offered `v0.78.0` when it publishes, where it used to compare equal and never be offered it. Build metadata (`+build.5`) carries no ordering weight, and published tags still never carry a suffix.

- B: pfm — `pfm install` links the machine-global agents, commands and skills into EVERY configured Claude account, not only the primary. The retire paths already walked every account while the install paths wrote the primary alone, so a second account (`~/.claude2`, say) had no global agents at all — `rr` was simply missing there. Two accounts whose registries alias one directory are linked once. `pfm doctor` gains one line per account, `doctor: global-agents account=N dir=<dir> state=linked|MISSING|CONFLICT|UNREADABLE`; every state but `linked` is a warning that names its fix, and an unreadable registry is never reported as an empty one. A host with no Professor clone (pfm installs without the blueprint) is reported as `state=NO-CLONE` — named, not a warning — while a clone that ships no agent sources stays a `NO-SOURCES` warning.
#### → For: hosts with more than one Claude account — run `pfm install --yes` once, then check the `doctor: global-agents` lines.

- B: pfm — `pfm update` no longer rolls itself back because live chats are older than it. The spawn audit dated its "born after the layer" line by the staged prompt's mtime, which an install leaves alone when the prompt's bytes don't change, so every chat launched before the `--settings` output-style flag counted as a broken spawn door, doctor exited 1, and the update's doctor gate undid the update. The line is now when this host's current spawn door went live: the later of the prompt's and the running pfm binary's mtime, both named in the report. Chats an older pfm launched report as PREDATES-LAYER (reload to carry the flag).

- B: pfm — a rolled-back update restores the hook files its install rewrote. The previous release's installer recognises only hooks it generates, so a hook only the newer release registered (e.g. `exit-intercept` on UserPromptSubmit) survived the rollback and ran a subcommand the restored binary lacks on every prompt. `pfm update` now snapshots every installer-owned hook file (each account's Claude settings, each Codex hooks file, and their ownership ledger) before the install and restores it on rollback, but only while the file still holds exactly what that install wrote. A file a live chat saved in the meantime is left alone and named as rollback residue.

- B: pfm — an unknown `pfm internal <name>` exits 1, not 2. Exit 2 is Claude Code's blocking hook code, so a hook registered by a different pfm version erased every prompt ("UserPromptSubmit operation blocked by hook") instead of reporting one non-blocking error that names the fix.

- B: pfm — `pfm update` builds its candidate with `-buildvcs=false`. The stage is a git worktree, whose `.git` file cmd/go does not treat as a VCS root, so any stray `.git` directory above it (an empty `$HOME/.git`) failed the build with "error obtaining VCS status".

- B: pfm — a process's birth time on Linux is the kernel's start tick plus boot time, not the `/proc/<pid>` directory's mtime. procfs creates that inode lazily, so the mtime read processes as minutes to hours younger than they are, skewing the spawn audit and Codex thread-to-pane matching.

- B: pfm — `pfm install` run from inside a git worktree of the source clone records the clone itself, not the worktree. A worktree is deleted once its work merges, which left the source marker, `pfm update`, and the global links pointing at nothing.

- B: pfm — `pfm install` and `pfm uninstall` no longer change numbers in the JSON files they rewrite. `~/.claude.json` and every account registry, Claude `settings.json`, and Codex `hooks.json` were decoded into Go floats and written back, so any integer beyond 2^53 (a counter or id) came back rounded — `9007199254740993` became `…992`. Those rewrites now decode numbers verbatim; malformed JSON is still refused.

- B: pfm — Codex chats can reach the fleet again. On macOS the shared MCP daemon (`pfm mcp serve`, the transport every Codex chat uses) ran on launchd's bare `/usr/bin:/bin:/usr/sbin:/sbin`, where tmux is not, so every chat tool a Codex chat called answered as if no chat were live: `chat_inject` refused with "matched no live chat" and `chat_whoami` found "no live Codex tmux seat". - B: pfm — Codex 0.154 chats are named without false alarms. 0.154 renames a thread without printing "Session renamed to", so `pfm chat new`, `pfm chat branch`, the post-`/clear` name re-apply and every dream seat reported a chat that was named on the first try as "never asked for a thread name" (and failed the dream seat), after typing `/rename` twice more into a pre-filled dialog. - B: pfm — `pfm chat open` (and the MCP `chat_open`) resumes a Codex or OpenCode chat on its own engine's account. - B: pfm — `make install` sweeps stale pfm processes on macOS too. ## Removed

- B: pfm — the chat MCP server drops `chat_goal` and `chat_reload`; two fewer tool descriptions ride in every session that loads the chat server. A goal is a one-line `/goal …` message sent with `chat_inject`, and `/wave:orchestrator` fires its builder that way; a reload is the shell command `pfm chat reload`, which alone carries the account, cache and `--then` settings. The CLI verbs are unchanged.
#### → For: anything that called `chat_goal{target, goal}` — send `chat_inject{target, message:"/goal <one line>"}` instead; anything that called `chat_reload` — run `pfm chat reload --sock <socket>` (or `/reload` inside the chat). Adopted projects: take the `/wave:orchestrator` template update from `pfm update check`.

- C: pfm — `/pfm:refresh` is gone as a command. It was never typed: `/pfm:release --from {live-root}` is the only caller, so the pass (cost law, scope scan, MISSING-SOURCE rulings, hunk classification, reviewed batches, closing regen) now lives beside the rules it applies in `$CDOCS/pfm/$REFS/refresh.md` § The pass, and release step 3 runs it from there. One fewer entry in every session's registry, the same capability: `refresh-map.json` still carries each template's live-source SHA, `refresh-scope.sh scan` still reports what changed since the last sync.

- B: templates — `/jc` and `/qa:live` are gone from the blueprint end to end, and so is every name derived from the first, but not the procedure they carried. The fix loop and the debug playbook are rehomed as `$CDOCS/wave/$REFS/{fix-core,debug-discipline}.md` and cited by `/wave:live`, which keeps its remediation lane (diagnose → fix → re-test → cleanup per the card, then a gitter commit per finding group). `gitter` renames JC-COMMIT to **COMMIT** — the plain code-plus-doc commit lane for a change that lands directly on `main`, listed in the dispatch table and confirmed from `gitter-history.md` like every other phase; `/documenter`'s JC-UPDATE mode is renamed FIX-UPDATE, with its `## JC-UPDATE` section renamed in all seven scope cards and in `documenter-fanout.js` — the same fold-in, run after a fix lands; `/dev`, `/rnd`, `/km` and `/audit:ai-output` stop handing found fixes to a command and report them instead. The public docs lose the hotfix-lane pitch with it.

- C: engines — `deep-rr`'s SKILL.md drops the `repo:` pointer to its retired standalone repo (it ships in-tree at `engines/deep-rr/` and `pfm install` symlinks it; nothing fetches it) and its description comes to cap. The two retired standalones, the research pipeline and the harvester MCP server, now say so in their GitHub descriptions and point at this framework.
